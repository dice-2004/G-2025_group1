## 📚 テンプレートマッチングの基本概念

### 五目並べにおけるテンプレートマッチング

テンプレートマッチングとは、盤面上のパターン（石の並び）を検出し、それぞれに評価値を付ける手法です。

**基本原理**:
```
5マスの窓を使ってパターンを検出:
[●][●][●][●][_] → 四連（FOUR）
[_][●][●][●][_] → 開いた三（OPEN_THREE）
[●][●][_][●][●] → 飛び四（BROKEN_FOUR）
```

---

## 🔧 新しい実装の手法

### 概要

各方向のライン（行・列・斜め）を**1回だけ完全に走査**し、スライディングウィンドウで5マス窓を評価します。

### ステップ1: ライン抽出

```c
// ライン全体を抽出（完全な1ライン）
static void extract_full_line(const int board[][BOARD_SIZE],
                               int start_x, int start_y,
                               int dx, int dy,
                               int line[], int *length) {
    int idx = 0;
    int x = start_x;
    int y = start_y;

    while (x >= 0 && x < BOARD_SIZE && y >= 0 && y < BOARD_SIZE) {
        line[idx++] = board[y][x];
        x += dx;
        y += dy;
    }
    *length = idx;
}
```

**動作**:
- 開始位置から方向(dx, dy)に沿って進む
- 盤面の端まで到達したら終了
- 抽出したラインと長さを返す

### ステップ2: スライディングウィンドウ評価

```c
int evaluate_line(const int line[], int length, int my_color) {
    // 長さ5未満は評価不要
    if (length < 5) {
        return 0;
    }

    // スライディングウィンドウ
    for (int i = 0; i <= length - 5; i++) {
        // 5マス窓 [i, i+1, i+2, i+3, i+4] を評価
        // パターンマッチング...
    }
}
```

**動作**:
- 1ライン内で5マス窓をスライドさせる
- 各窓でパターンを検出し、スコアを加算

```c
//   → 黒石3個、空白2個、右側開いている（左は盤端扱い）

// 窓3 [位置2-6]: [●, ●, _, _, ○]
//   → 黒石2個、空白2個、白石1個

// 窓6 [位置5-9]: [_, ○, ○, ○, ○]
//   → 白石4個、空白1個（相手のパターン）

// 窓7 [位置6-10]: [○, ○, ○, ○, _]
//   → 白石4個、空白1個（相手のパターン）
//   → 相手のFOUR: -9000点

// ... 続く

// 最終スコア: +5000 +1000 -9000 -9000 + ... = 合計スコア
```

**重要**: この行は**1回だけ**評価され、すべての5マス窓が漏れなく評価されます。

## 🚨 重大な問題点の発見

### 問題: スコアの重複カウント

#### 詳細分析

**シナリオ**: 以下の盤面
```
[●] [●] [●] [●] [●] [_] [_] [_] [_] [_] [_] [_] [_] [_] [_]
```

**新実装の評価**:
```
窓1 [0-4]: [●, ●, ●, ●, ●] → FIVE: +100000点
窓2 [1-5]: [●, ●, ●, ●, _] → FOUR: +10000点
窓3 [2-6]: [●, ●, ●, _, _] → THREE: +1000点
窓4 [3-7]: [●, ●, _, _, _] → TWO: +100点
窓5 [4-8]: [●, _, _, _, _] → ONE: +10点

合計: +111110点
```

**問題点**:
- この5連は**本来100000点のパターン1つ**
- しかし、窓をスライドさせることで、**部分的なパターン（FOUR、THREE、TWO、ONE）も加算される**
- 実際のスコア: 100000点
- 計算されたスコア: 111110点
- **過剰評価: +11110点（11.1%の誤差）**

現在の実装では、5マス窓でしか評価していないため、以下のパターンを検出できません：

```
1 │ _ _ _ ● _ _ _ _
2 │ _ _ ● ● ● _ _ _
3 │ _ ● ● ● ● ● _ _
4 │ _ _ ● ● ● _ _ _
5 │ _ _ _ ● _ _ _ _

```

位置(3,3)に黒石を置くと、**縦横2つの四が同時に成立**：
- 横方向: [_, ●, ●, ●, ●, ●, _]（6連中に四2つ）
- 縦方向: [_, ●, ●, ●, ●, ●, _]（6連中に四2つ）

**現在の実装の評価**:
```c
// 横方向のライン評価
```

**問題**:
- **四四パターン（FOUR_FOUR: 45000点）を検出していない**

- 6マス以上の範囲を見る必要があるパターンは検出不可能

## 📊 正確性の評価まとめ

### ✅ 正しく動作する点

1. **すべての5マス窓を評価**: 見逃しなし
2. **重複評価の排除**: 同じラインを2回評価しない
3. **5マス未満の無駄排除**: 効率的
4. **飛びパターンの検出**: 可能

### ❌ 問題がある点

1. **スコアの重複カウント**:
   - 同じ石が複数の窓で評価され、スコアが重複加算される
   - 長いパターンほど誤差が大きい
   - 例: 5連 → 111110点（正: 100000点）

2. **複合パターンの検出不足**:
   - 5マス窓では四四、四三などの複合パターンを検出できない
   - 6マス以上の範囲が必要なパターンは評価不可

3. **評価値の不整合**:
   - 開いた四: 過小評価（21110点 vs 正: 50000点）
   - 五連: 過剰評価（111110点 vs 正: 100000点）

## 🔍 旧実装との比較

### 旧実装の特徴

```c
// 各マスについて周辺9マスを評価
for (int y = 0; y < BOARD_SIZE; y++) {
    for (int x = 0; x < BOARD_SIZE; x++) {
        if (board[y][x] == my_color) {
            total_score += evaluate_position(board, x, y, my_color);
        }
    }
}

// evaluate_positionの中で4方向を評価
int evaluate_position(...) {
    // 中心±4マスの範囲を抽出（9マス）
    extract_line(board, x, y, dx, dy, line, &length, 9);
    score += evaluate_line(line, 9, color);
}
```

### 旧実装の問題点

1. **重複評価が多い**: 同じ区間を何度も評価（93%重複）
2. **無駄な計算**: 5マス未満の斜めラインも評価

### 旧実装の利点

1. **局所的評価**: 各マス周辺のみを見るため、評価の重複は9マス範囲内に限定
2. **スコアの妥当性**: 同じパターンが複数回評価されるが、それぞれのマスの「価値」として合算される

## 🤔 新実装の正確性評価

### 理論的正確性

**❌ 正確ではありません**

理由:
1. **スコアの意味が変わる**:
   - 旧: 各マスの「価値」の合計
   - 新: 各ラインの「パターンスコア」の合計
   - これらは**異なる概念**

2. **重複カウントの問題**:
   - 長いパターンの過剰評価
   - 短いパターンの過小評価

3. **複合パターンの検出不足**:
   - 四四、四三などの重要なパターンを見逃す

### 実用的正確性

**🔺 部分的に正確**

- 単純なパターン（単独の三、四など）は正しく評価される
- 複雑なパターン（複合、長い連など）は誤評価される
- AIの強さには**影響がある**可能性が高い
