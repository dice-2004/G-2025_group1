## 🎯 問題の発見

### 発見された3つの重大な問題

#### 問題1: ゲームIDの完全欠如

**発見内容**:
```csv
# 元のopening_book.csv（問題あり）
1,7,7,初手は中央
2,8,8,黒の斜め
2,8,7,黒の横
2,7,8,黒の縦
3,6,6,白の対角
```

**問題点**:
- コメントに "game X" の記述が一切ない
- `extract_game_id()` が全ての行で `-1` を返す
- ゲーム単位選択が完全にバイパスされる

**影響**:
```c
// find_opening_move() の動作
if (game_id == -1) {
    // ゲームID検出失敗
    // フォールバック処理へ
    // → ゲーム単位選択が機能しない
}
```

#### 問題2: 手順の論理的不整合

**発見内容**:
```csv
2,8,8,黒の斜め
2,8,7,黒の横
2,7,8,黒の縦
```

**問題点**:
- 同じ手番に3つの異なる手が存在
- どの手が同じゲームの一部か不明
- 手順の整合性が保証されない

**影響**:
- 最初の手は「斜め」だが、次は「横」や「縦」かもしれない
- 戦略的な一貫性が失われる
- ユーザーの洞察「手の順番がある」が実現されない

#### 問題3: 学習システムとの不整合

**学習システムの出力**:
```csv
1,7,7,Learned from win (game 5)
2,8,8,Learned from win (game 5)
```

**手動定石の形式**:
```csv
1,7,7,初手は中央
2,8,8,黒の斜め
```

**問題点**:
- 学習定石にはゲームIDがある
- 手動定石にはゲームIDがない
- 混在時の動作が不明確

## 🎯 実装の技術的詳細

### コード変更

**変更ファイル**: `opening_book.csv` のみ

**理由**:
- 既存のコードが既に対応済み
- `extract_game_id()` が実装済み
- `find_opening_move()` がゲーム単位選択を実装済み
- データフォーマットの修正のみで動作

### extract_game_id() の動作

**実装**:
```c
int extract_game_id(const char* comment) {
    char* pos = strstr(comment, "game ");
    if (pos == NULL) {
        return -1;  // ゲームID not found
    }

    int game_id = atoi(pos + 5);  // "game " の後の数字
    return game_id;
}
```

**Before の動作**:
```
Input: "初手は中央"
strstr() → NULL
return -1
```

**After の動作**:
```
Input: "Manual: 斜め攻撃 (game 101)"
strstr() → " (game 101)"
atoi("101)") → 101
return 101
```

### find_opening_move() の動作

**フローチャート**:
```
┌─────────────────────────┐
│ find_opening_move()     │
│ 呼び出し                │
└───────────┬─────────────┘
            │
            v
    ┌───────────────┐
    │ move_count == 0? │
    └───────┬───────┘
            │Yes
            v
    ┌──────────────────┐
    │ selected_game_id  │
    │ = -1 (リセット)   │
    └──────┬───────────┘
            │No
            v
    ┌──────────────────────┐
    │ move_count == 1?      │
    └──────┬───────────────┘
            │Yes
            v
    ┌──────────────────────────┐
    │ ゲームIDをランダム選択    │
    │ selected_game_id = 選択ID │
    └──────┬───────────────────┘
            │No
            v
    ┌──────────────────────────┐
    │ selected_game_id を使用   │
    │ して定石を検索            │
    └──────┬───────────────────┘
            │
            v
    ┌──────────────┐
    │ 定石を返す   │
    └──────────────┘
```

**Before の動作**:
```c
// ゲームID検出
int game_id = extract_game_id(comment);
// → 常に -1

// ゲームID選択
if (selected_game_id == -1) {
    // game_id == -1 なので、選択できない
    // フォールバックへ
}
```

**After の動作**:
```c
// ゲームID検出
int game_id = extract_game_id(comment);
// → 101, 102, 103, 201～208

// ゲームID選択（move_count == 1）
if (selected_game_id == -1) {
    // 11個のゲームIDからランダム選択
    selected_game_id = 203;  // 例: 峡月
}

// 以降の手（move_count == 2～5）
if (game_id == selected_game_id) {
    // 同じゲームの手を使用
    return move;
}
```

### トラブルシューティング

#### 問題: ゲームIDが認識されない

**原因**: opening_book.csv のフォーマットが間違っている

**解決策**:
```csv
# 正しいフォーマット
1,7,7,Manual: 斜め攻撃 (game 101)
       ^^^^^^^^^^^^^^^^^^^^^^
       "game XXX" が必須
```

#### 問題: 同じ定石ばかり選ばれる

**原因**: ゲームIDの範囲が狭い

**解決策**: opening_book.csv にゲームを追加

#### 問題: 学習定石が追加されない

**原因**: 学習モードが無効

**解決策**:
```
config.txt:
LEARNING_MODE=PRACTICE
```
