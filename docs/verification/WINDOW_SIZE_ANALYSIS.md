# 抽出サイズと窓サイズの詳細分析

## 📋 前提条件

### 現在の実装
```c
static void extract_line(const int board[][BOARD_SIZE], int x, int y, int dx, int dy,
                         int line[], int *length, int max_len) {
    int idx = 0;
    int nx = x - dx * 4;  // 中心から4マス戻る
    int ny = y - dy * 4;

    for (int i = 0; i < max_len && idx < max_len; i++) {
        line[idx++] = board[ny][nx];
        nx += dx;
        ny += dy;
    }
    *length = idx;
}
```

### キーポイント
- `x, y`: 評価対象の中心マス
- `x - dx * 4`: 中心から4マス戻った位置から開始
- その後、`max_len`マス分を前進しながら抽出

## 提案1: 8マス抽出 + 8マス窓

### 抽出処理
```c
extract_line(board, 7, y, 1, 0, line, &length, 8);

開始位置: x = 7 - 1*4 = 3
抽出範囲: x=3から8マス分

結果:
line[0] = board[3] = ●
line[1] = board[4] = ●
line[2] = board[5] = ●
line[3] = board[6] = ●
line[4] = board[7] = ● (中心)
line[5] = board[8] = _
line[6] = board[9] = _
line[7] = board[10] = _

抽出結果: [●][●][●][●][●][_][_][_]
          ↑           ↑
        開始        中心
```

### 窓評価（8マス窓 = 窓1つだけ）
```c
// 8マス窓評価
for (int i = 0; i <= length - 8; i++) {  // i = 0 のみ
    // line[0]～line[7]を評価
}

窓1 [インデックス0-7]: [●][●][●][●][●][_][_][_]
```

### 評価
```
パターン: 5連（●が5個）+ 空白3個
スコア: FIVE = 100000点

両側チェック:
  左側: i==0 なので左は「盤端または確認不可」
  右側: line[8]が存在しない → 確認不可
```

### ❌ 問題点
1. **両側の状況を確認できない**
   - 抽出範囲が8マスなので、窓の外側（左右）の情報がない
   - 「開いているか」を判定不可能

2. **窓が1つしかない**
   - スライディングウィンドウができない
   - `i <= length - 8` → `0 <= 8 - 8` → `i = 0` のみ

3. **中心から左側が1マスしか見えない**
   - 開始位置が`x-4`だが、8マス抽出なので`x-4`～`x+3`まで
   - 中心(x)から左に4マス、右に3マスという非対称

   - 11マス抽出なら`x - dx * 5`（5マス戻る）に変更必要

## 🔄 修正案: 9マス抽出 + 5マス窓（スライディング）【現在の実装】

### 抽出処理
```c
extract_line(board, 7, y, 1, 0, line, &length, 9);

開始位置: x = 7 - 1*4 = 3
抽出範囲: x=3から9マス分

結果: [●][●][●][●][●][_][_][_][_]
```

### 窓評価（5マス窓をスライディング）
```c
for (int i = 0; i <= length - 5; i++) {  // i = 0, 1, 2, 3, 4
    窓1 [i=0]: [●][●][●][●][●]
    窓2 [i=1]: [●][●][●][●][_]
    窓3 [i=2]: [●][●][●][_][_]
    窓4 [i=3]: [●][●][_][_][_]
    窓5 [i=4]: [●][_][_][_][_]
}
```

### 評価
```
窓1: 5連
  両側チェック:
    左側: i==0なので確認不可
    右側: line[5] = _ (開いている)
  スコア: FIVE

窓2: 4連 + 1空白
  両側チェック:
    左側: line[0] = ● (閉じている)
    右側: line[6] = _ (開いている)
  スコア: FOUR (片側開き)

窓3～5: THREE, TWO, ONE
```

### ✅ 利点
1. **5つの窓でスライディング評価**
2. **両側の状況をある程度確認可能**（窓の前後2マスずつ）
3. **現在の実装で動作している**

### ⚠️ 問題点
1. **5マス窓では複合パターン検出困難**
   - 開いた四（6マス）は検出できない
   - 四四（7～8マス）も検出不可

## 🏆 最終結論

### 正しい理解

1. **「抽出 = 窓」は間違い**
   - 抽出：データを取り出す範囲
   - 窓：抽出したデータ内でスライドさせながら評価する範囲

2. **窓 < 抽出 が必要**
   - 理由：窓の外側（左右）の状況を確認するため
   - 例：8マス窓なら、左右に各1～2マス余裕が必要 → 10～12マス抽出

3. **スライディングウィンドウの重要性**
   - 1つの窓だけでは不十分
   - 複数の窓で評価することで、さまざまなパターンを検出

## 🎯 最終推奨：**11マス抽出 + 6マス窓（スライディング）**

### 理由

1. **6マス窓で開いた四を検出可能**
   - `[_][●][●][●][●][_]` = 6マス

2. **11マス抽出で両側確認可能**
   - 6マス窓 + 左右各2.5マス = 11マス
   - 各窓の左右の状況を確認できる

3. **スライディングで6つの窓**
   - `i = 0, 1, 2, 3, 4, 5`
   - 多角的な評価

4. **五目並べの戦術に最適**
   - 5連 + 開いているか（±1マス）= 6マス窓
   - その周囲を確認（±2.5マス）= 11マス抽出
