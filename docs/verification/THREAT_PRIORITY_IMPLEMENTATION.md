# 脅威手優先順位変更レポート

**実施日**: 2025年10月15日
**対象ファイル**: `gomoku_ai.c`
**変更内容**: 序盤定石よりも脅威手（TSS）の検出を優先するように変更

---

## 📋 実装内容

### 目的
序盤定石（Opening Book）を使用する前に、脅威手（Threat Space Search: TSS）を優先的にチェックすることで、戦術的に正しい手順を保証する。

### 変更理由

#### Before（問題のある動作）
```
フェーズ1: 序盤定石チェック（最初の5手）
  → 定石が見つかれば、それを優先

フェーズ2: 脅威手チェック（TSS）
  → 五連、開いた四、開いた三などをチェック

問題点:
❌ 序盤定石が脅威手より優先される
❌ 相手の開いた四があっても、定石を優先してしまう
❌ 勝ち手があっても、定石を優先してしまう
❌ 戦術的に不正確な手を打つ可能性
```

#### After（修正後の動作）
```
フェーズ1: 脅威手チェック（TSS）- 最優先
  ✅ 自分の勝ち手（五連）
  ✅ 相手の勝ち手を防ぐ（五連防御）
  ✅ 自分の開いた四（最優先攻撃）
  ✅ 相手の開いた四を防ぐ（最優先防御）
  ✅ 自分の開いた三または間空き三

フェーズ2: 序盤定石チェック（脅威がない場合のみ）
  ✅ 最初の5手で定石を参照
  ✅ ただし脅威手が優先される

フェーズ3: 相手の開いた三を防ぐ

フェーズ4: Alpha-Beta探索
```

## 🔄 変更内容の詳細

### 変更箇所: gomoku_ai.c の ai_move() 関数

#### Before（旧実装）
```c
// フェーズ1: 序盤定石のチェック
if (move_count < 5) {
    if (find_opening_move(board, move_count, &book_x, &book_y)) {
        *pos_x = book_x;
        *pos_y = book_y;
        return 0;  // ここで終了（脅威手をチェックしない！）
    }
}

// フェーズ2: 詰みと必死のチェック (TSS)
if (find_winning_move(board, com, &win_x, &win_y)) {
    // ...
}
```

**問題点**:
1. 定石が見つかった時点で `return 0` してしまう
2. その後の脅威手チェックが実行されない
3. 相手の開いた四や勝ち手を見逃す

#### After（新実装）
```c
// フェーズ1: 詰みと必死のチェック (TSS) - 最優先
if (find_winning_move(board, com, &win_x, &win_y)) {
    *pos_x = win_x;
    *pos_y = win_y;
    printf("[AI] Winning move executed!\n");
    return 0;  // 勝ち手があれば最優先
}

if (find_threat_move(board, com, &win_x, &win_y)) {
    *pos_x = win_x;
    *pos_y = win_y;
    printf("[AI] Threat defended!\n");
    return 0;  // 相手の勝ち手を防ぐ
}

attack_level = find_strong_attack_move(board, com, &win_x, &win_y);
if (attack_level == 2) {  // 開いた四
    *pos_x = win_x;
    *pos_y = win_y;
    printf("[AI] Open four attack executed!\n");
    return 0;  // 開いた四は最優先攻撃
}

defense_level = find_strong_defense_move(board, com, &win_x, &win_y);
if (defense_level == 2) {
    *pos_x = win_x;
    *pos_y = win_y;
    printf("[AI] Defended opponent's open four!\n");
    return 0;  // 相手の開いた四を防ぐ
}

if (attack_level == 1) {  // 開いた三 or 間空き三
    *pos_x = win_x;
    *pos_y = win_y;
    printf("[AI] Strong attack move executed!\n");
    return 0;
}

// フェーズ2: 序盤定石のチェック（脅威手より後に実行）
if (move_count < 5) {  // 脅威がない場合のみ定石を使用
    int book_x, book_y;
    if (find_opening_move(board, move_count, &book_x, &book_y)) {
        *pos_x = book_x;
        *pos_y = book_y;
        printf("[AI] Opening book move: (%d, %d)\n", *pos_x, *pos_y);
        return 0;
    }
}
```

**改善点**:
1. ✅ 脅威手を最優先でチェック
2. ✅ 定石は脅威がない場合のみ使用
3. ✅ 戦術的に正しい手順を保証

## 🎯 優先順位の詳細

### 新しい優先順位（上から順に実行）

| 優先度 | フェーズ | 内容 | 条件 |
|--------|---------|------|------|
| **1** | TSS | 自分の勝ち手（五連） | 常に最優先 |
| **2** | TSS | 相手の勝ち手を防ぐ（五連防御） | 常に最優先 |
| **3** | TSS | 自分の開いた四 | 最優先攻撃 |
| **4** | TSS | 相手の開いた四を防ぐ | 最優先防御 |
| **5** | TSS | 自分の開いた三・間空き三 | 強力な攻撃 |
| **6** | Opening Book | 序盤定石 | move_count < 5 **かつ** 脅威なし |
| **7** | 初手特別処理 | 中央配置 | move_count == 0 **かつ** 定石なし |
| **8** | TSS | 相手の開いた三を防ぐ | 防御手 |
| **9** | Alpha-Beta | 通常探索または反復深化 | 上記すべてが該当しない場合 |

