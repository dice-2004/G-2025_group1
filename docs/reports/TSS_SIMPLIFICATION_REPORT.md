# TSS機能の簡素化：開いた四のみに限定

## 作成日
2025年10月15日

## 問題の背景

### ユーザーからの指摘

実戦で以下の問題が発生：

1. **過剰な防御**
   ```
   局面:
     7 8 9
   2 . . ●
   3 . . ●
   4 ○ ● ●

   AIの判定: (7,2)を「開いた三」として防御
   問題: これは開いた三ではない（上端で塞がれている）
   ```

2. **TSS探索の過剰実行**
   ```
   [TSS] Total positions checked: 204
   [TSS] Total threats found: 6

   問題:
   - すべての空きマスをチェック
   - 開いた三、間空き三も探索
   - 本来のAlpha-Beta探索の時間が不足
   ```

### ユーザーの要求

> TSSに関してはこれを打たないと負ける手やこれを打てば勝てる手などの検出のみにしてください

つまり：
- **必勝手**：これを打てば勝てる（五連、開いた四）
- **必敗防御**：これを打たないと負ける（相手の五連、開いた四を防ぐ）
- **それ以外**：Alpha-Beta探索に任せる

## 実施した修正

### 修正1: TSSの範囲を限定

#### 修正前

**検出対象**:
1. 五連（必勝）
2. 開いた四（必勝の1手前）
3. 開いた三（必勝の2手前）← 削除
4. 間空き三（必勝の2手前）← 削除

**問題点**:
- 開いた三・間空き三の判定が不正確
- 全マスをスキャン（204マス）
- 計算時間が膨大
- Alpha-Beta探索の時間が不足

#### 修正後

**検出対象**:
1. ✅ 五連（必勝）
2. ✅ 開いた四（必勝の1手前）
3. ❌ ~~開いた三~~（削除）
4. ❌ ~~間空き三~~（削除）

**改善点**:
- シンプルで高速
- 開いた四のみスキャン
- Alpha-Beta探索に時間を使える

### 修正2: `find_strong_attack_move()`の簡素化

#### 修正前（logics/TSS.c: 470-580行目）

```c
int find_strong_attack_move(...) {
    // 全マスをスキャン
    for (int y = 0; y < BOARD_SIZE; y++) {
        for (int x = 0; x < BOARD_SIZE; x++) {
            // 開いた四をチェック
            if (has_open_four(...)) {
                candidates[count++] = ...;
            }

            // 開いた三をチェック ← 削除
            if (has_open_three(...)) {
                candidates[count++] = ...;
            }

            // 間空き三をチェック ← 削除
            if (has_split_three(...)) {
                candidates[count++] = ...;
            }
        }
    }

    // 候補をソート
    qsort(candidates, ...);

    // 最良の候補を返す
    return result_level;  // 2=開いた四, 1=開いた三
}
```

#### 修正後（logics/TSS.c: 470-500行目）

```c
// 開いた四のみを探す（開いた三は探索しない - 過剰防御防止）
int find_strong_attack_move(...) {
    if (g_config.debug_level >= 2) {
        printf("[TSS] Searching for OPEN-FOUR only\n");
    }

    // 開いた四のみを探す
    for (int y = 0; y < BOARD_SIZE; y++) {
        for (int x = 0; x < BOARD_SIZE; x++) {
            if (board[y][x] == STONE_SPACE) {
                // 禁じ手チェック
                if (color == STONE_BLACK && is_forbidden(...)) {
                    continue;
                }

                // 開いた四をチェック
                if (has_open_four(...)) {
                    *attack_x = x;
                    *attack_y = y;
                    if (g_config.debug_level >= 1) {
                        printf("[TSS] ★ OPEN-FOUR found at (%d, %d) ★\n", x, y);
                    }
                    return 2;  // 開いた四
                }
            }
        }
    }

    if (g_config.debug_level >= 2) {
        printf("[TSS] No open-four found\n");
    }
    return 0;  // 見つからず
}
```

**改善点**:
- ✅ 候補リストの作成不要
- ✅ ソート不要
- ✅ メモリ割り当て不要
- ✅ 開いた四が見つかったら即座に返す
- ✅ コードが50%以上削減

**削除された機能**:
- ❌ 自分の開いた三攻撃

## AI手選択の新しいフロー

### 修正後の優先順位

```
ai_move() 実行フロー

1. [必勝手] 自分の五連
   → あれば即座に実行

2. [必敗回避] 相手の五連を防ぐ
   → あれば即座に実行

3. [必勝の1手前] 自分の開いた四
   → あれば即座に実行

4. [必敗回避] 相手の開いた四を防ぐ
   → あれば即座に実行

5. [序盤] 定石（move_count < 5）
   → あれば実行

6. [探索] Alpha-Beta / 反復深化探索
   → 評価関数でスコアリング
   → 開いた三、間空き三もここで評価
   → 最善手を選択
```

### Alpha-Beta探索での評価

開いた三・間空き三は評価関数でスコアリング：

```c
// evaluation.c の評価パターン

パターン              スコア      説明
─────────────────────────────────────
開いた四               8000      必勝の1手前（TSSで検出）
開いた三               800       有利な攻撃手
間空き三               300       有利な攻撃手
開いた二               100       弱い攻撃手
```

**利点**:
- 局面全体を評価
- 複数の開いた三を比較
- 攻守のバランスを考慮
- 深い読みが可能
