## 定石チェックの条件

### gomoku_ai.c の実装

```c
// フェーズ2: 序盤定石のチェック
if (move_count < 5) {  // 最初の5手は定石を参照
    int book_x, book_y;
    if (find_opening_move(board, move_count, &book_x, &book_y)) {
        *pos_x = book_x;
        *pos_y = book_y;
        printf("[AI] Opening book move: (%d, %d)\n", *pos_x, *pos_y);
        return 0;
    }
}
```

### 条件の意味

```c
if (move_count < 5)
```

この条件は：
- move_count = 0, 1, 2, 3, 4 → **true** → 定石をチェック ✅
- move_count = 5 → **false** → 定石をチェックしない ❌

### 今回のケース

```
move_count = 5（6手目）
5 < 5 は false
→ 定石チェックをスキップ
→ Alpha-Beta探索に移行
```

## なぜ6手目で定石が使われなかったのか

### 理由1: 条件による制限

```c
if (move_count < 5)  // 5手目まで（move_count=0,1,2,3,4）
```

- 6手目（move_count=5）は条件を満たさない
- 定石チェックがスキップされる

### 理由2: 定石データの範囲

仮に条件を満たしても：
- opening_book.csvには move_number = 1～5 のみ
- move_number = 6 のデータは存在しない
- find_opening_move() は定石を見つけられない

## 設計の意図

### 定石の役割

**序盤定石**（Opening Book）:
- 対局の最初の数手を記録
- 定跡として知られた良い手順
- 一般的に **3～7手** 程度

### 現在の設計

```
序盤5手: 定石を参照
6手目以降: Alpha-Beta探索で戦略的判断
```

**理由**:
1. 定石は「序盤の型」を覚えるもの
2. 中盤以降は局面に応じた柔軟な判断が必要
3. Alpha-Beta探索の方が適切

### 五目並べでの一般的な定石

| 対局 | 定石の範囲 |
|------|----------|
| 将棋 | 20～40手 |
| 囲碁 | 30～60手 |
| チェス | 10～20手 |
| **五目並べ** | **3～7手** |
| オセロ | 10～20手 |

五目並べは盤面が広く、早い段階で変化が多いため、**定石は短め**が一般的です。

## 今回のログでの動作

### 実際の流れ

```
1. AIの手番（6手目、move_count=5）

2. TSSチェック
   - 五連: なし
   - 開いた四: なし
   → スキップ

3. 定石チェック
   if (move_count < 5)  // 5 < 5 は false
   → スキップ ← ここが問題

4. Alpha-Beta探索
   → 実行された
   → (9,7) を選択（スコア62778）
```

### 定石をチェックしていたら

仮に `if (move_count < 6)` だったら：

```
3. 定石チェック
   if (move_count < 6)  // 5 < 6 は true
   → find_opening_move(board, 5, ...)
   → move_number = 6 を検索
   → opening_book.csv にデータなし
   → 見つからず

4. Alpha-Beta探索
   → 実行される（結果は同じ）
```

つまり、**条件を変更しても、定石データがないため結果は同じ**です。

## 推奨される対応

### 短期的対応（すぐに実施可能）

**現状維持**:
- 定石は5手まで
- 6手目以降はAlpha-Beta探索
- これは合理的な設計

**理由**:
1. 五目並べの定石は短めが一般的
2. Alpha-Beta探索で柔軟に対応できる
3. 学習データが蓄積される

### 中期的対応（推奨）

**定石を7手に拡大**:

1. opening_book.csv に6～7手目を追加（各ゲーム11個 × 2手 = 22手）
2. gomoku_ai.c の条件を変更: `if (move_count < 7)`
3. 学習によって自動的に良い6～7手目が蓄積される

### 長期的対応

**学習による自動拡張**:
- 勝利した試合の6～7手目も自動記録
- 長い定石が自然に蓄積される
- 現在の学習システムは5手までしか記録していない
