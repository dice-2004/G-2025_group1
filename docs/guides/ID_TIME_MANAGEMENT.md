## 🎯 概要

このガイドでは、**Iterative Deepening（反復深化探索）における時間管理機能**について説明します。

特に、**制限時間が来たときに、進行中の深度の結果を破棄して、ひとつ前の完了した深度の結果を返す**という重要な機能について詳しく解説します。

---

## 🔄 Iterative Deepening の基本動作

### 動作フロー

```
深度1で探索 → 結果を保存 → 完了 ✅
  ↓
深度2で探索 → 結果を保存 → 完了 ✅
  ↓
深度3で探索 → 結果を保存 → 完了 ✅
  ↓
深度4で探索開始...
  ↓
  【時間切れ！】
  ↓
深度4の結果を破棄 ❌
  ↓
深度3の結果を返す ✅ （ひとつ前の完了した深度）
```

---

## ⏱️ 時間管理の仕組み

### 1. 二段階のチェック

#### ステージ1: 探索開始前のチェック
```c
// 次の深度を開始する前に時間をチェック
現在時刻 = 測定();
経過時間 = 現在時刻 - 開始時刻;

if (経過時間 > 制限時間 × 閾値) {
    // 次の深度の探索を開始しない
    // 前の深度の結果を返す
    break;
}
```

**目的**: 次の深度の探索を開始しても完了できなさそうなら、そもそも開始しない

#### ステージ2: 探索完了後のチェック
```c
// 深度の探索が完了した後に時間をチェック
探索完了時刻 = 測定();
経過時間 = 探索完了時刻 - 開始時刻;

if (経過時間 > 制限時間) {
    // この深度の結果を破棄
    // ひとつ前の深度の結果を返す
    *best_x = prev_x;  // 前の結果に戻す
    *best_y = prev_y;
    best_score = prev_score;
    break;
}
```

**目的**: 探索中に時間切れになった場合、その不完全な結果を使わず、前の確実な結果を使う

## 🎚️ 時間閾値の設定

### config.txt での設定

```txt
# Iterative Deepening 時間制限閾値（0.0～1.0）
# この値 × TIMEOUT_MS の時間までに深度探索を開始します
ID_TIME_THRESHOLD=0.8
```

### 閾値の意味

| 設定値 | 意味 | 挙動 |
|-------|------|------|
| 0.7 | 70% | 制限時間の70%を超えたら次の深度に進まない（保守的） |
| 0.8 | 80% | 制限時間の80%を超えたら次の深度に進まない（推奨） |
| 0.9 | 90% | 制限時間の90%を超えたら次の深度に進まない（積極的） |
| 0.95 | 95% | 制限時間の95%を超えたら次の深度に進まない（超積極的） |

### 閾値の選び方

#### 保守的設定（0.7）
```txt
ID_TIME_THRESHOLD=0.7
```
- ✅ 時間切れのリスクが低い
- ✅ 確実に完了した結果を返せる
- ❌ 探索深度が浅くなる可能性

**推奨シーン**:
- 大会や本番環境
- 確実性を重視
- タイムオーバーのペナルティが厳しい場合

#### バランス型設定（0.8）【デフォルト・推奨】
```txt
ID_TIME_THRESHOLD=0.8
```
- ✅ 時間切れのリスクと探索深度のバランスが良い
- ✅ ほとんどのケースで適切
- ✅ 実用的な深度を確保

**推奨シーン**:
- 通常の対戦
- 迷ったらこれ
- ほとんどの状況に対応

#### 積極的設定（0.9）
```txt
ID_TIME_THRESHOLD=0.9
```
- ✅ より深い探索が可能
- ✅ 強い手を見つけやすい
- ❌ 時間切れのリスクがやや高い

**推奨シーン**:
- 練習モード
- より強い手を探したい
- 時間制限に余裕がある場合

## 🛠️ 実装の技術的詳細

### コード構造

```c
int iterative_deepening(...) {
    // 前の深度の結果を保持する変数
    int prev_x = -1, prev_y = -1, prev_score = 0;
    int completed_depth = 0;

    for (depth = 1; depth <= max_depth; depth++) {
        // [ステージ1] 探索開始前のチェック
        double elapsed = 経過時間を計算();
        if (elapsed > time_limit * threshold) {
            // 次の深度を開始しない
            break;
        }

        // 探索を実行
        int score = alpha_beta_search(...);

        // [ステージ2] 探索完了後のチェック
        elapsed = 経過時間を再計算();
        if (elapsed > time_limit) {
            // この深度の結果を破棄、前の結果を返す
            *best_x = prev_x;
            *best_y = prev_y;
            best_score = prev_score;
            break;
        }

        // 探索成功 - 前の結果を保存してから更新
        prev_x = *best_x;
        prev_y = *best_y;
        prev_score = best_score;

        *best_x = temp_x;
        *best_y = temp_y;
        best_score = score;
        completed_depth = depth;
    }

    return best_score;
}
```

### キーポイント

1. **prev_x, prev_y, prev_score**: 前の深度の結果を保存
2. **completed_depth**: 完了した最大深度を記録
3. **二段階チェック**: 開始前と完了後で時間を確認
4. **結果の巻き戻し**: 時間切れ時は前の結果に戻す

## ❓ FAQ

### Q1: 閾値を1.0にしたらどうなりますか？
**A**: 時間制限ギリギリまで探索しますが、時間切れのリスクが非常に高くなります。推奨しません。

### Q2: 閾値を0.5にしたらどうなりますか？
**A**: 非常に保守的になり、時間を十分に使えません。探索が浅くなります。

### Q3: 時間切れになった深度の結果は使われますか？
**A**: いいえ、破棄されます。前の完了した深度の結果が使われます。これが今回の重要な改善点です。

### Q4: 閾値はゲーム中に変更できますか？
**A**: いいえ、config.txtを編集してゲームを再起動する必要があります。

### Q5: DEBUG_LEVEL=1で時間切れの様子を確認できますか？
**A**: はい、"Time limit exceeded during depth X search" というメッセージで確認できます。

## 🎯 まとめ

### 重要なポイント

1. ✅ **時間制限が来たら、ひとつ前の深度の結果を返す**
   - 不完全な結果を使わない
   - 確実な結果を返す

2. ✅ **閾値で動作を調整可能**
   - config.txtで簡単に変更
   - 0.7～0.9の範囲で調整
   - デフォルト0.8が推奨

3. ✅ **二段階のチェック**
   - 探索開始前: 次の深度を開始するか判断
   - 探索完了後: 結果を採用するか判断

4. ✅ **デバッグ情報が充実**
   - DEBUG_LEVEL=1で基本情報
   - 時間切れの様子を確認可能
