## 概要

このガイドでは、五目並べAIの学習機能を効果的に活用する方法を説明します。AIは対局を重ねることで、勝ちやすいパターンを学習し、徐々に強くなります。

### 学習システムの特徴

- **パターンベース学習**: 20種類の戦術パターン（五並び、四並び、三並びなど）の勝率を記録
- **定跡学習**: 序盤の定跡（決まった手順）を学習し、opening_book.csvに蓄積
- **自動調整**: 勝ちやすいパターンの評価値を自動的に上げ、負けやすいパターンを下げる
- **継続的成長**: 対局を重ねるほど強くなる

## 学習システムの仕組み

### 1. パターン学習（評価値の自動調整）

AIは以下の20種類のパターンを認識し、それぞれの勝率を記録します。

#### 攻撃パターン（自分の石）
1. **五並び** (SCORE_FIVE): 100000点 - 勝利確定
2. **四並び** (SCORE_FOUR): 10000点 - 次で勝てる
3. **オープン四** (SCORE_OPEN_FOUR): 5000点 - 止められない四
4. **三並び** (SCORE_THREE): 1000点 - 次で四を作れる
5. **オープン三** (SCORE_OPEN_THREE): 800点 - 両端が空いている三
6. **二並び** (SCORE_TWO): 100点 - 次で三を作れる
7. **オープン二** (SCORE_OPEN_TWO): 80点 - 両端が空いている二
8. **一つ** (SCORE_ONE): 10点 - 最初の一手
9. **オープン一** (SCORE_OPEN_ONE): 8点 - 両端が空いている一つ
10. **分断された四** (SCORE_BROKEN_FOUR): 2000点 - 穴のある四

#### 防御パターン（相手の石）
11. **相手の五並び** (SCORE_OPP_FIVE): -100000点 - 負け
12. **相手の四並び** (SCORE_OPP_FOUR): -10000点 - 次で負ける
13. **相手のオープン四** (SCORE_OPP_OPEN_FOUR): -5000点 - 止められない
14. **相手の三並び** (SCORE_OPP_THREE): -1000点 - 防ぐ必要あり
15. **相手のオープン三** (SCORE_OPP_OPEN_THREE): -800点 - 要注意
16. **相手の二並び** (SCORE_OPP_TWO): -100点 - 警戒
17. **相手のオープン二** (SCORE_OPP_OPEN_TWO): -80点 - 警戒
18. **相手の一つ** (SCORE_OPP_ONE): -10点 - 最初の一手
19. **相手のオープン一** (SCORE_OPP_OPEN_ONE): -8点 - 警戒
20. **相手の分断された四** (SCORE_OPP_BROKEN_FOUR): -2000点 - 危険

### 学習の仕組み

#### ステップ1: 対局結果の記録
```
対局終了時:
- 使用したパターンを記録
- 勝ち/負けをカウント
```

#### ステップ2: 勝率の計算
```
勝率 = 勝利数 / 総対局数
例: 15勝 / 28対局 = 53.6%勝率
```

#### ステップ3: 調整係数の計算
```
調整係数 = (勝率 - 0.5) × 3.0
範囲: -1.5 ～ +1.5

例:
- 勝率80% → 調整係数 = (0.8 - 0.5) × 3.0 = +0.9
- 勝率30% → 調整係数 = (0.3 - 0.5) × 3.0 = -0.6
```

#### ステップ4: 評価値の調整
```
調整後の評価値 = 基本評価値 × (1 + 調整係数 × 調整率)
調整率 = 0.20 (20%)

例: オープン三(基本800点)で勝率80%の場合
調整後 = 800 × (1 + 0.9 × 0.20) = 800 × 1.18 = 944点
```

### 2. 定跡学習（Opening Book）

序盤の手順を記録し、次回以降の対局で参照します。

#### 定跡データの構造
```csv
game_id,move_number,x,y,color,category,note
123,1,7,7,black,learning,center opening
123,2,7,8,white,learning,standard response
123,3,6,7,black,learning,diagonal attack
...
```

#### ゲームIDの範囲
- **1-49, 51-99**: 手動登録の定跡（基本戦術）
- **101-149, 151-199**: プロ棋譜（高度な戦術）
- **200-599, 600-999**: 学習データ（AIが対局から学習）

#### 定跡の選択ロジック
1. **練習モード（PRACTICE）**: ランダムに選択（多様な経験）
2. **本番モード（PRODUCTION）**: 勝率の高いゲームを優先選択

## 学習の進め方

### フェーズ1: 初期トレーニング（1-50対局）

**目的**: 基本パターンの勝率データを集める

**推奨設定**:
```
SEARCH_DEPTH=4
TIMEOUT_MS=5000
LEARNING_MODE=PRACTICE
DEBUG_LEVEL=2
```

**進め方**:
1. **自己対局**: AIどうしで対局させる（高速で大量にデータ収集）
2. **多様な初手**: 色々な場所に初手を打つ（中央、隅、辺など）
3. **ログ確認**: `DEBUG_LEVEL=2`で学習状況を監視

**期待される変化**:
- パターンの使用回数が増加
- 調整係数が徐々に収束（±0.3〜±0.8程度）
- 定跡データが50-100ゲーム程度蓄積

**確認方法**:
```bash

# wins/totalが記録されているか確認
```

## 学習データの管理

### データファイルの場所

```
プロジェクトルート/
├── opening_book.csv          # 定跡データ
├── patterns_extended.csv     # パターン学習データ
└── config.txt                # 設定ファイル
```

### opening_book.csv（定跡データ）

**構造**:
```csv
game_id,move_number,x,y,color,category,note
123,1,7,7,black,learning,center opening
123,2,7,8,white,learning,standard response
```

**フィールド説明**:
- `game_id`: ゲームID（200-999が学習データ）
- `move_number`: 手番（1から始まる）
- `x, y`: 盤面の座標（0-14）
- `color`: 黒(black)または白(white)
- `category`: learning（学習データ）
- `note`: メモ（オプション）

**管理方法**:
```bash
# バックアップ（学習前）
copy opening_book.csv opening_book_backup.csv

# 勝率の低いゲームを削除（手動編集）
# game_idが200-999の範囲で、負け続けているゲームを削除

# 復元
copy opening_book_backup.csv opening_book.csv
```

---

### patterns_extended.csv（パターン学習データ）

**構造**:
```csv
pattern_name,wins,losses,draws,total_games,adjustment_factor
Open Three,45,42,0,87,0.103
Open Four,32,18,0,50,0.840
...
```

**フィールド説明**:
- `pattern_name`: パターン名
- `wins`: 勝利数
- `losses`: 敗北数
- `draws`: 引き分け数
- `total_games`: 総対局数
- `adjustment_factor`: 調整係数（-1.5〜+1.5）

**管理方法**:
```bash
# バックアップ（学習前）
copy patterns_extended.csv patterns_extended_backup.csv

# リセット（学習をやり直す場合）
del patterns_extended.csv
# プログラムを起動すると自動的に新しいファイルが作成される

# 復元
copy patterns_extended_backup.csv patterns_extended.csv
```

## 学習効果の確認

### 方法1: ログを確認（DEBUG_LEVEL=1）

**学習更新のログ**:
```
[Learning] Updated pattern: Open Three (wins: 45, total: 87, factor: 0.103)
[Learning] Updated pattern: Open Four (wins: 32, total: 50, factor: 0.840)
```

**確認ポイント**:
- `total`: 総対局数が増えているか
- `factor`: 調整係数が変化しているか（±0.3以上なら効果あり）

---

### 方法2: 詳細ログを確認（DEBUG_LEVEL=2）

**評価値調整のログ**:
```
[Evaluation] Pattern: Open Three
  Base score: 800
  Adjustment factor: 0.655
  Adjusted score: 905 (+13%)
```

**確認ポイント**:
- `Adjusted score`: 基本スコアからどれだけ変化したか
- パーセンテージ: ±10%以上変化していれば学習効果あり

---

### 方法3: データファイルを直接確認

**patterns_extended.csvを開く**:
```csv
pattern_name,wins,losses,draws,total_games,adjustment_factor
Open Three,45,42,0,87,0.103
Open Four,32,18,0,50,0.840
Broken Four,12,8,0,20,0.600
```

**分析ポイント**:
1. **総対局数**: 50以上あれば信頼できるデータ
2. **勝率**: 40-60%の範囲が理想的
3. **調整係数**: ±0.5以上なら学習効果が出ている

**勝率の計算**:
```
勝率 = wins / total_games × 100

例: Open Three
勝率 = 45 / 87 × 100 = 51.7%
```

### 方法4: 実戦テスト

**手順**:
1. 学習前のAIと10対局
2. 学習後のAIと10対局

## トラブルシューティング

### Q: 学習データが更新されない

**確認事項**:
1. `LEARNING_MODE=PRACTICE`になっているか
   ```
   # config.txtを確認
   LEARNING_MODE=PRACTICE
   ```

2. ファイルの書き込み権限があるか
   ```bash
   # Windowsの場合、管理者権限で実行してみる
   ```

3. ログで学習が実行されているか確認
   ```
   DEBUG_LEVEL=2
   # ログに[Learning] Updated pattern...が出るか確認
   ```

**解決方法**:
- `LEARNING_MODE`を`PRACTICE`に設定
- ファイルの読み取り専用属性を解除
- プログラムを再起動

---

### Q: 調整係数が0.000のまま変わらない

**原因**: 対局数が不足している（3対局未満）

**解決方法**:
1. 最低3対局を実行する
2. `DEBUG_LEVEL=2`でログを確認
   ```
   [Learning] Pattern: Open Three
     Total games: 3 (min: 3)
     Win rate: 66.7%
     Adjustment factor: 0.500
   ```

3. `MIN_GAMES_FOR_LEARNING`の設定を確認（デフォルト: 3）

---

### Q: 学習しても強くならない

**原因**:
1. 調整率が小さすぎる（`PATTERN_ADJUST_RATE`）
2. 対局数が少ない（50対局未満）
3. 同じパターンばかり使っている

**解決方法**:
1. `PATTERN_ADJUST_RATE`を確認（推奨: 0.20）
   ```c
   // learning.cの設定
   #define PATTERN_ADJUST_RATE 0.20
   ```

2. 最低100対局は実行する

3. 多様な戦術で対局する
   - 色々な初手を試す
   - 攻撃と防御をバランスよく

---

### Q: 特定のパターンだけ勝率が極端

**原因**: そのパターンの使用頻度が偏っている

**例**:
```csv
Open Four,50,5,0,55,1.500  # 勝率91%
Open Three,10,40,0,50,-1.500  # 勝率20%
```

**解決方法**:
1. データをリセットして再学習
   ```bash
   del patterns_extended.csv
   ```

2. より多様な対局を実行

3. 手動で調整係数を編集（非推奨）
   ```csv
   # 極端な値を中間値に修正
   Open Four,50,5,0,55,0.800
   Open Three,10,40,0,50,-0.800
   ```

---

### Q: opening_book.csvが大きくなりすぎた

**原因**: 学習データ（game_id 200-999）が増えすぎている

**解決方法**:
1. 古いデータを削除
   ```bash
   # バックアップを取る
   copy opening_book.csv opening_book_backup.csv

   # game_id 200-399のデータを削除（手動編集）
   # または勝率の低いゲームを削除
   ```

2. 定期的にクリーンアップ（推奨: 500ゲームごと）

3. ファイルサイズの目安
   - 1000ゲーム: 約100KB
   - 5000ゲーム: 約500KB
   - 10000ゲーム: 約1MB（この辺りで整理推奨）

---
