## 詳細フロー: Phase 1 - TSS（詰み探索）

### 脅威空間探索（Threat Space Search）

```
┌──────────────────────────────────────────┐
│ Priority 1: 自分の5連チェック              │
│  全空きマスで試行 → 5連成立？             │
│    YES → その手を返す（即勝利）            │
│    NO  → 次へ                             │
└────────┬─────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────┐
│ Priority 2: 相手の5連防御                 │
│  相手が次に打って5連？                    │
│    YES → その位置を防御                   │
│    NO  → 次へ                             │
└────────┬─────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────┐
│ Priority 3: 開いた四の攻撃                │
│  自分が開いた四を作れる？                 │
│    YES → その手を返す（次確実）            │
│    NO  → 次へ                             │
└────────┬─────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────┐
│ Priority 4: 相手の脅威防御                │
│  相手の開いた四/片側四/開いた三？         │
│    YES → その位置を防御                   │
│    NO  → 次へ                             │
└────────┬─────────────────────────────────┘
         │
         ▼
┌──────────────────────────────────────────┐
│ Priority 5: 攻撃的な手                    │
│  四連作成 or 複数の開いた三？             │
│    YES → その手を返す                     │
│    NO  → Phase 2へ                       │
└──────────────────────────────────────────┘
```

**特徴**:
- **O(n)の計算量**: 空きマス数nに比例
- **確実な詰み**: 1-2手詰みを確実に発見
- **防御も完璧**: 相手の脅威を見逃さない

## 詳細フロー: Phase 3 - Alpha-Beta探索

### 探索の流れ

```
alpha_beta(board, depth, alpha, beta, is_max)
  │
  ├─ [1] 置換表プローブ
  │      同じ局面を探索済み？
  │        YES → キャッシュ結果を返す
  │        NO  → 次へ
  │
  ├─ [2] 終端条件チェック
  │      depth == 0 or ゲーム終了？
  │        YES → evaluate_board() で評価
  │        NO  → 次へ
  │
  ├─ [3] 合法手生成
  │      - 空きマスの中から候補を抽出
  │      - 禁じ手を除外（黒の場合）
  │      - 既存の石の周辺2マスを優先
  │
  ├─ [4] 各手について探索
  │      for each move in legal_moves:
  │        ├─ make_move(move)
  │        ├─ update_zobrist_hash(hash, move)
  │        ├─ score = -alpha_beta(depth-1, ...)  # 再帰
  │        ├─ undo_move(move)
  │        │
  │        ├─ score > alpha ?
  │        │   └─ alpha = score
  │        │       best_move = move
  │        │
  │        └─ score >= beta ?
  │            └─ break  # Beta枝刈り（探索打ち切り）
  │
  └─ [5] 置換表ストア
         結果をキャッシュに保存
```

## 詳細フロー: 反復深化探索（ID法）

### 時間制限への対応

```
iterative_deepening(board, color, time_limit)
  │
  ├─ 開始時刻を記録
  │
  ├─ depth = 1 から開始
  │
  └─ while (残り時間 > 0):
      │
      ├─ alpha_beta_search(board, depth)
      │   └─ この深度で最善手を探索
      │
      ├─ 最善手を更新
      │
      ├─ 時間チェック
      │   └─ 残り時間 < 次の深度の推定時間？
      │       YES → 探索終了
      │       NO  → 次へ
      │
      └─ depth++  # 深度を1つ深く
```

**利点**:
- ⏱️ **時間厳守**: 制限時間を確実に守る
- 📈 **段階的深化**: 浅い探索 → 深い探索
- 🎯 **最善手保証**: いつでも現時点の最善手あり

## 詳細フロー: 学習フェーズ

### 対戦終了時の学習

```
finish_game_record(result)
  │
  ├─ [1] 統計更新
  │      total_games++
  │      wins++ or losses++
  │      win_rate = wins / total_games
  │
  ├─ [2] パターン分析
  │      analyze_game_patterns(result)
  │        ├─ 序盤フェーズ (1-10手)
  │        │   └─ TWO, ONE の調整値累積
  │        │
  │        ├─ 中盤フェーズ (11-20手)
  │        │   └─ THREE, OPEN_THREE の調整値累積
  │        │
  │        └─ 終盤フェーズ (21手以降)
  │            └─ FOUR, OPEN_FOUR の調整値累積
  │
  ├─ [3] スコア適用 (3試合ごと)
  │      apply_pattern_learning()
  │        └─ learning_rate = 0.05 / sqrt(total_games)
  │            new_score = old_score + adjustment * learning_rate
  │
  ├─ [4] 定石学習 (勝利時のみ)
  │      learn_opening_moves()
  │        └─ 序盤5手をopening_book.csvに追記
  │
  └─ [5] データ保存
         save_learning_data()
           └─ learning_data.dat に保存
```

## まとめ: プログラムの流れ

### 3つの主要フェーズ

1. **探索フェーズ**
   - TSS → 序盤定石 → Alpha-Beta
   - 最善手を決定

2. **対戦フェーズ**
   - 手を記録
   - 勝敗判定

3. **学習フェーズ**
   - パターン分析
   - スコア調整
   - データ保存

### キーポイント

- ✅ **段階的判断**: 詰み → 定石 → 探索
- ✅ **効率的探索**: 置換表で高速化
- ✅ **継続的学習**: 対戦データから自動改善
- ✅ **柔軟な設計**: モジュール分割で拡張容易
