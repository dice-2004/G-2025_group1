## スライド5: コアアルゴリズム②

### Zobrist Hashing + 置換表

#### Zobrist Hashing
```
盤面を64ビットの数値で表現
→ O(1)で同一局面判定
```

#### 置換表
```
┌──────────────────────────────┐
│ Hash  │ Score │ Depth │ Move │
├──────────────────────────────┤
│ 0x1A3F│  2340 │   4   │ (8,8)│
│ 0x2B4C│ -1250 │   3   │ (7,9)│
└──────────────────────────────┘

サイズ: 262,144エントリ (~4MB)
ヒット率: 40-70%
```

**効果**: 探索を **2-5倍高速化**

## スライド6: ビットボード技術

### 通常の盤面表現 vs ビットボード

#### 通常の2次元配列
```c
int board[15][15];  // 225バイト
```

#### ビットボード
```c
uint64_t black[4];  // 32バイト
uint64_t white[4];  // 32バイト
uint64_t fill[4];   // 32バイト
```

### 利点
✅ メモリ効率 (225バイト → 96バイト)
✅ ビット演算で高速処理
✅ キャッシュヒット率向上

## スライド7: 評価関数

### テンプレートマッチング

9マスのウィンドウで連続パターンを認識

```
パターン例:
●●●●●     → FIVE (100,000点)
_●●●●_    → OPEN_FOUR (50,000点)
○●●●_     → FOUR (10,000点)
_●●●_     → OPEN_THREE (5,000点)
```

### 評価値計算

```
総評価値 = Σ(自分のパターン) - Σ(相手のパターン)
```

**特徴**: 局面の優劣を数値で表現

## スライド9: 学習システム - パターン最適化

### 学習アルゴリズム

```
新スコア = 現在のスコア + (調整値 × 学習率 × 勝敗係数)

学習率 = 基本率 (0.05) / √(総試合数)
```

### 対戦フェーズ別の学習

| フェーズ | 手数 | 学習するパターン |
|---------|------|----------------|
| 序盤 | 1-10手 | ONE, TWO |
| 中盤 | 11-20手 | THREE, OPEN_THREE |
| 終盤 | 21手以降 | FOUR, OPEN_FOUR |

### 学習率の減衰

```
試合1:  0.0500 (大きく変化)
試合10: 0.0158
試合50: 0.0071 (安定化)
```
