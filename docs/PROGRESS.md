## 2026-11-10 ブラウザで遊べる G2 と、その自動公開 (公開スレッド)

**やったこと**
- G2 を `zig cc -target wasm32-wasi` で WebAssembly にした (`engine/web/build.sh`、zig は `pip install ziglang`)。
  エンジンのコード (`engine/src`) は変えず、入口 `engine/web/g2_wasm.c` を足しただけ。wasm32 は long が 32 ビットで、
  `search.c` の「ノード数の上限なし」の `1L << 40` が壊れる (VCT がすぐ打ち切られる) ので、ビルド用の写しで置き換えている
- 静的サイト `engine/web/site/`: 盤面 UI (連珠・自由・ちょうど五、黒白、思考時間 0.5〜5 秒、待った、禁じ手の × 表示、手順)。
  思考は Web Worker の中で、最小の WASI (`wasi.js`) で動かす。スマホ幅でも横にはみ出さない (Playwright で確認)
- CD: `.github/workflows/pages.yml`。`claude/dev` への push (engine/src・engine/web・このファイルが変わったとき) で
  ビルド → `engine/web/smoke_test.js` (3 ルールで合法手・五を打つ・三三の判定) → GitHub Pages に公開。PR ではビルドと確認だけ

**結果**
- wasm 1.36MB。同じ局面・1 秒で、手元のネイティブ 104 万 nps に対し wasm (Node) 76 万 nps (約 73%)、Chromium でも 70〜75 万 nps
- 公開には Pages の設定 (Source を GitHub Actions に、github-pages 環境に claude/dev を許可) が要る。dice に依頼済み。
  Actions の初回実行はビルドと動作確認が成功し、公開だけ Pages 未有効で失敗 (想定どおり)
- claude.ai のアーティファクト版も公開した (`engine/web/make_artifact.py` で 1 ファイルにまとめる。wasm を base64 で埋め込み 1.8MB)。
  https://claude.ai/artifact/CZdJbuBNsMpSExkEvfJ9uc 。自動更新されないので節目ごとに作り直す
- dice の判断で GitHub Pages は使わず、アーティファクト版を本命にした。ワークフローは CI (ビルドと動作確認) として残し、
  Pages への公開はリポジトリ変数 `PAGES_ENABLED=true` のときだけにした
- 対局データの自動収集: アーティファクトの db に、G2 が 6 手目以降を打つたびと終局時に 1 局 1 文書で記録
  (`games/<利用者 id>/g/<対局 id>`、形式 `g2-game/1`)。記録できるのは Contributor 以上 (dice と組織のメンバー) の対局だけ。
  強化スレッドは `ArtifactData` で読む。形式と取り出し方は engine/web/README.md
- 組織外 (dice の友人) の対局はアーティファクトでは記録できない (db は読むだけ、外への通信も止められている) ので、
  dice の判断で GitHub Pages 版に戻し、記録先を Google Apps Script (スプレッドシート、`engine/web/collector/Code.gs`) にした。
  秘密情報なし・新しいアカウント不要。読み出しは `engine/web/fetch_games.py`。Pages への公開は `engine/web/pages.enabled` があるときだけ。
  Code.gs は模擬の SpreadsheetApp で書き込み・上書き・読み出しを確認、ページからの POST は Playwright で確認 (1 局 5 回、最後に勝敗付き)。
  残り: dice の設定 (Apps Script のデプロイ、Pages の有効化) → URL を config.js に書く → 公開と記録の確認 → アーティファクトを消す
- 中で G2 が動いていると分かるように、wasm にビルド元のコミットを埋め込み (`g2_version`、ページに「エンジン: G2 <コミット>」とソースへのリンク)、
  思考ごとに決め手 (探索・VCF・VCT・ブックなど)・深さ (最大の深さ)・評価・ノード数・時間・ノード/秒・読み筋を表示し、記録に残すようにした

## 2026-11-09 機械学習が入っていないかの監査 (コード変更なし)

**結論**: 深い機械学習 (ニューラルネット・NNUE・全マスを学習モデルで評価する方式) はエンジンに入っていない。

- `engine/src`: ファイルを開く処理 (`fopen` 等) が 1 つもなく、外部の重み・モデルを読まない。`pbrain-g2` は 100KB で libc 以外に依存せず、
  空のディレクトリで動かしても開くファイルはない (strace で確認)。評価は手で決めたパターン (線パターン 12 種 × 4 方向の組み合わせ 13 種 + 脅威 8 種) の表引き
- 学習した数値は `eval.c` の 59 個 (line 12 + combo 13 + opp_scale + tempo + threat 32)。手で決めた特徴量の線形和を sigmoid で
  Rapfi 古典評価のラベル (1.5 万局面) に合わせるロジスティック回帰 (Texel 法) で、閾値・重みの調整の範囲
- `eval_table.c` の 460 個の補正 (パターンの組ごと、Rapfi 古典評価 2 万局面) は既定無効 (`use_table = 0`、自己対戦 -35 で不採用)
- 開局ブック: 287 局面、最大 5 石 (6 手目まで)。手と評価は Rapfi 古典評価の解析 (`analysis_*.jsonl`) から自動生成。
  Rapfi は `bench/setup_rapfi.sh` で本体だけビルドし NNUE の重みを置かないので、NNUE の出力は入り得ない
- gomocalc (NNUE) は `bench/web/sites/gomocalc.py` で対局するだけ。`engine/src` には名前も出てこない。
  ブックで解析する局面の一部は gomocalc 戦で出た局面だが、手は古典 Rapfi で選んでいる
- 旧エンジン (リポジトリ直下 `logics/learning.c`) は勝敗で 20 個のパターン倍率を変える軽い学習。G2 には含まれない
- 小さな注意: `eval.c:7-8` のコメントは「6000 局面」だが、今の重みは 1.5 万局面での再調整 (v0.4)。Rapfi 古典評価の表そのものが
  作者の調整を経ている可能性はあるが、ニューラルネットではない

  - 開局 40 個のうち 18 個は片方の色がほぼ必ず勝つ (G2 が有利な色で 30 回中 15〜29 勝、逆の色で 0〜1 勝)。G2 の 23 勝前後のうち約 15 勝はこの「有利な色の 18 枠」

  - これまでの「自己対戦では +26〜+50 だが Rapfi では差なし」は、効かないのではなく物差しが粗くて見えていない可能性がある (mcp のような大きな悪化は見える)

**探索スレッドに渡した API** (受けへの利用はルートの候補作りに探索スレッドが組み込む)
- `int dfpn_vct(Board *b, int attacker, long max_nodes, int max_ms, DfpnResult *res)` (`engine/src/dfpn.h`):

- 既定値: `p_vct_pct=20` (ルートの自分の VCT に上限時間の 20%)、`p_ts_pct=20` (その後に ts で 20%、`ts_win` は `engine/src/ts.h`)、`p_vct_dfpn=1` (0 で旧 `vct_solve`)、
