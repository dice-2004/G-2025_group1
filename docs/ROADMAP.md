# 強化ロードマップ

**目標**: アルゴリズム中心 (重い機械学習なし、閾値・重みの軽い調整はあり) の五目並べ AI で、
世界の Web サイト・アプリの最高難易度に勝つ ([TARGETS.md](./TARGETS.md))。
ゆくゆくは機械学習系トップ (Rapfi NNUE / Gomocup 上位) と同じ水準にする。

進み具合は [PROGRESS.md](./PROGRESS.md)、測定結果は [benchmarks/](./benchmarks/) に記録する。

## 現状 (2026-10-22 時点の評価)

授業版 v3.4 (`gomoku_ai.c` + `logics/`) の測定結果は [benchmarks/2026-10-22_baseline.md](./benchmarks/2026-10-22_baseline.md)。
要点:

- 1手読みの貪欲ボットにも負け越す (連珠ルールで 5勝2分13敗)。黒番で特に弱く、三三の禁じ手負けが多い
- 自前の禁じ手判定 (`is_forbidden`) が三三を見逃す。授業審判とも判定が食い違う
- 探索は素朴な minimax 型 αβ。ノードごとに盤面全体の `memcpy`、終局判定、全盤評価をしていて遅い。
  手の並べ替え・PVS・脅威探索 (VCF/VCT) がない。置換表の境界種別の付け方にも誤り
- ルールベースの「勝ち手/防御/攻撃」ショートカットが探索より先に手を決めてしまう
- `evaluate_position` にスタック破壊バグがあった (2026-10-22 修正済み、`int line[9]` に 11 マス書き込み)

結論: **探索エンジンは作り直す**。既存コードは授業版として残し、新エンジンを `engine/` に作る。

## 設計方針 (新エンジン)

- 言語は C (C11)、`-O2` で gcc/clang/MSVC どれでもビルドできること。外部ライブラリなし
- 入口を 2 つ用意: Gomocup プロトコル (`pbrain-g2`) と授業の `calcPutPos` (授業の大会用)
- ルール: freestyle / standard (ちょうど五) / renju。授業審判の癖への対応は別レイヤ
- 世界の強豪 (Rapfi, Yixin, Embryo) と同じ定石的な構成を目指す:

| 部品 | 内容 |
|---|---|
| 盤面 | パディング付き 1 次元配列。各マス・4 方向の「線パターン」を差分更新 (11 マス窓のビット列 → 表引き) |
| パターン | 五 / 活四 / 四 / 活三 / 三 / 活二 … をルール別に表で判定。連珠の禁じ手は表 + 再帰 (偽の三三を除く) |
| 手生成 | パターン点で候補を絞る。相手の四には必ず止める、相手の活三には防ぎ手と自分の四だけ、などの強制手枝刈り |
| 脅威探索 | VCF (四追い) を高速に、VCT (三・四追い) を防御集合付きで。必要に応じて df-pn (証明数探索) |
| 探索 | 反復深化 + PVS + aspiration window、置換表 (Zobrist)、killer / history、LMR、脅威による延長 |
| 評価 | マスごとの (自分パターン, 相手パターン) の組み合わせ表の和 + 手番補正。重みは自己対局で軽く調整 |
| 時間管理 | 1 手の目安と上限、安定したら早めに打つ |
| 序盤 | 開局ブック (Rapfi 等で事前解析して作る。対局中は使うだけ) |

## フェーズ

各フェーズは PDCA で回す。

- **Plan**: 変更の仮説を 1 つ決める (例: 「VCF を入れれば T1 相手の取りこぼしが消える」)
- **Do**: ブランチで実装、単体テスト
- **Check**: `bench/match.py` で前バージョンと対局 (互角開局・先後入替)、Rapfi の段と `bench/ladder.py`。
  戦術テスト集 (詰み局面) の正答率と時間
- **Act**: 良くなったら `claude/dev` にマージ。結果を PROGRESS.md と benchmarks/ に記録。悪ければ戻す

### Phase 0: 計測基盤 (完了)
- Gomocup アダプタ、レフェリー (freestyle/standard/renju/授業審判)、対局・ラダー・開局生成ツール
- Rapfi (古典評価) をノード制限で段階的な相手にする
- 現状の強さを測定

### Phase 1: 新エンジンの土台

状況 (2026-10-22): 項目 1・2 完了 (engine/、G2 v0.1)。項目 3 (VCF) が次。

1. 盤面・差分パターン・ルール判定 (連珠禁じ手含む)。`bench/rules.py` と大量ランダム局面で一致検証
2. Gomocup 入口と `calcPutPos` 入口。最初は「1手読み + 強制手」で greedy に勝つところまで
3. VCF ソルバ + 戦術テスト集 (Rapfi で詰みが出た局面を自動収集)

**完了条件**: 新エンジンが legacy と greedy に大差で勝ち、VCF テスト集を高い正答率で解く

### Phase 2: 本格探索
1. PVS + 置換表 + 手順並べ替え + 反復深化 + 時間管理
2. VCT と探索への統合 (脅威延長・必至の検出)
3. 評価関数 (パターン組み合わせ表) と自己対局による重み調整 (Texel 法 / SPSA 程度の軽い学習)

**完了条件**: Rapfi-n10k 〜 n100k に勝ち越す (T1 の Web AI に勝てる水準の見込み)

### Phase 3: 目標サイトに挑戦 (T1 → T2)
1. ルールごとの開局ブック
2. 実サイト・アプリと対局 (ブラウザ自動操作か手動) し、負けた局面を戦術テスト集に入れて弱点を潰す
3. マルチスレッド (Lazy SMP)

**完了条件**: T1 全サイト、T2 の主要アプリの最高難易度に勝ち越す

### Phase 4: 世界最強級へ (T3)
1. 証明数探索 (df-pn) による深い必勝読み、探索の細かい改良
2. 評価の表を大きくして (マスの周囲パターン)、自己対局データで重みを当てる (NN は使わず表の学習)
3. 基準を Rapfi NNUE (rapfi-networks の重み) に上げて差を測る

**完了条件**: Rapfi 古典評価に同時間で勝ち越し、Rapfi NNUE 相手に差を縮める

### 並行トラック: 授業の大会
授業審判 (`.libgomoku.c`) は連珠と判定が違い、連珠では合法な手でも負けにされる
(例: `O X X . x X X X O` の x を四四と判定)。授業で使う場合は、AI 側で審判と全く同じ判定を
再現して候補手から外す (審判の `c33Board`/`c44Board` の状態も手ごとに追跡する)。
`bench/match.py --rule class --check N` で検証する。

## やらないこと

- 大きなニューラルネットの学習と推論 (目標の趣旨から外れるため)。ただし比較相手としては使う
- 授業審判 (`gomoku.c`, `.libgomoku.c`) の変更 (変更禁止の配布物)
