環境: クラウドコンテナ 4 コア、各エンジン 1 スレッド、1 手 1000 ms (`--tc 1000`)。
legacy は `pbrain-legacy` (TIMEOUT_MS = 600、LEARNING_MODE=PRODUCTION、評価関数のスタック破壊修正後)。
開局はルール別の互角開局 40 個 (`bench/openings/*_balanced.txt`) を先後入替で 80 局。

## 授業審判と連珠の判定差

class ルールの実戦 30 局から黒番の局面 836 個、石の近くの候補手 36,726 個を取り、
授業審判 (状態 c33Board/c44Board を局面まで再生した上で) と連珠判定を比べた。

| | 件数 |
|---|---:|
| 両方とも反則 | 94 |
| 授業審判だけ反則 (連珠では合法) | 27 |
| 連珠だけ反則 (授業審判は見逃す) | 5 |

例: 行が `O X X . x X X X O` (x が着手) のとき、連珠では五にならない (長連になる) ので四ではないが、
授業審判は `XX.XX` を飛び四、`XXXX` を四と別々に数え、2 つの起点が 3 マス離れているので四四と判定する。

## 読み取り

- legacy は Rapfi の最弱設定 (深さ 2) にも 1 局も勝てない。目標の T1 (深さ 4〜6 の minimax サイト) にも届いていないと見られる
- Rapfi の段は 1 段ごとにはっきり差がつくので、新エンジンの進捗の物差しとして使える
- 新エンジンの最初の関門: greedy と legacy に大差、次に rapfi-d2 → rapfi-n1k → ... と順に勝ち越す
